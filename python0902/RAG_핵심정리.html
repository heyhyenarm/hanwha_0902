Retrieval-Augmented Generation

RAG 핵심 정리

RAG는 질문과 관련된 외부 자료를 먼저 검색하고, 그 자료를 Context로 LLM에 전달해 근거 있는 답변을 생성하는 방식입니다.

2

RAG 8단계

01

Load

PDF, 웹, DB 등의 문서와 출처 정보를 읽어옵니다.

02

Split

문맥을 보존하며 문서를 작은 Chunk로 나눕니다.

03

Embed

Chunk와 질문의 의미를 실수 Vector로 변환합니다.

04

Store

Vector, 원문, 출처를 Vector DB에 영구 저장합니다.

05

Retriever

질문과 가장 관련 있는 Chunk를 검색합니다.

06

Prompt

질문, Context, 답변 규칙을 하나의 입력으로 만듭니다.

07

LLM

제공된 Context를 근거로 자연어 답변을 생성합니다.

08

Chain

검색, 재시도, 생성, 출처 표시의 순서를 제어합니다.

3

헷갈리기 쉬운 개념

Embedding ≠ Fine-tuning

저장과 학습은 다릅니다

Embedding은 의미를 Vector로 표현하는 과정입니다. Fine-tuning은 특정 작업이나 말투에 맞게 모델의 가중치를 추가 학습하는 과정입니다.

Retriever ≠ Retry

검색과 재시도는 다릅니다

Retriever는 자료를 찾아오는 검색기입니다. 결과가 부족할 때 질문 재작성, 재검색, Reranking 같은 Retry 흐름을 추가할 수 있습니다.

4

Vector DB 선택

PostgreSQL + pgvector

관계형 데이터와 Vector를 SQL, JOIN, 트랜잭션으로 함께 관리할 때 적합합니다.

Qdrant

전용 Vector DB의 유사도 검색, Payload, 필터 구조를 집중적으로 학습할 때 적합합니다.

5

왜 개발자가 필요한가?

문서→ Chunk→ Embedding→ 검색→ Context→ 답변
  • 문서 갱신과 접근 권한 설계
  • Chunk 크기와 검색 방식 실험
  • 검색 실패 시 재시도 처리
  • 답변의 근거와 출처 검증
  • 개인정보와 Prompt Injection 방어
  • 정확도, 응답 시간, 비용 평가

한 줄 정리

RAG는 LLM이 더 많이 기억하게 만드는 기술이 아니라, 질문에 필요한 근거를 찾아 정확하게 참고하도록 만드는 시스템입니다.
