# RAG란?

RAG(Retrieval-Augmented Generation)는 검색 증강 생성 방식임. 사용자의 질문과 관련된 외부 문서를 먼저 검색한 뒤, 검색 결과를 LLM에 함께 전달해 답변을 생성하는 구조임.

모델이 학습하지 않은 최신 정보나 사내 문서도 참고할 수 있으며, 답변의 근거를 제공하기 쉬워짐. 다만 검색 결과의 품질이 낮으면 답변 품질도 낮아질 수 있음.

## 내가 학습하는 RAG 흐름 8단계

1. **문서 로드**: PDF, 웹페이지, 데이터베이스 등의 문서를 Loader로 읽어옴.
2. **텍스트 분할**: 긴 문서를 검색하기 적절한 작은 청크로 나눔.
3. **임베딩**: 텍스트 청크를 의미를 표현하는 벡터로 변환함.
4. **벡터 스토어**: 임베딩과 원문을 벡터 데이터베이스에 저장함.
5. **리트리버**: 질문과 관련성이 높은 문서 청크를 검색함.
6. **프롬프트**: 사용자의 질문과 검색된 문맥을 LLM에 전달할 형식으로 구성함.
7. **LLM**: 프롬프트를 바탕으로 답변 생성함.
8. **체인**: 로드부터 답변 생성까지의 구성 요소와 실행 순서를 연결함.

흐름 요약: `문서 로드 → 텍스트 분할 → 임베딩 → 벡터 스토어 → 리트리버 → 프롬프트 → LLM → 체인`

# OpenAI API 키 호출 핵심 정리

## 1. 기본 호출 코드

`OpenAI()`가 `OPENAI_API_KEY` 환경 변수 자동으로 읽음.

```python
from openai import OpenAI

client = OpenAI()

response = client.responses.create(
    model="gpt-5.6-luna",
    input="This is an API connection test. Reply briefly.",
)

print(response.output_text)
print(response.usage)
```

## 2. API 키 설정

CMD에서 현재 창에만 임시 설정 가능함.

```cmd
set OPENAI_API_KEY=sk-여기에_API_키
python keytest.py
```

환경 변수 존재 여부만 확인하고 키 자체는 출력하지 않음.

```cmd
if defined OPENAI_API_KEY (echo API key is set) else (echo API key is not set)
```

PC 재부팅 후에도 계속 사용하려면 사용자 환경 변수로 저장함. `setx`로 저장한 값은 새로 연 CMD 창부터 적용됨.

```cmd
setx OPENAI_API_KEY "sk-여기에_API_키"
```

PC 변경 또는 사용 종료 시 기존 PC에서 API 키 환경 변수 반드시 삭제해야 함. 사용자 환경 변수 삭제 명령은 다음과 같음.

```cmd
reg delete "HKCU\Environment" /v OPENAI_API_KEY /f
```

삭제 후 열려 있는 CMD와 VS Code 다시 시작해야 함. `setx`로 저장한 키는 기존 CMD 창에 남아 있을 수 있으므로 창을 닫아야 함. 키 노출 시 OpenAI 대시보드에서도 해당 키 폐기해야 함.

## 3. `.env` 파일 사용

1. 패키지 설치

```cmd
pip install openai python-dotenv
```

2. `.env` 파일 작성

```text
OPENAI_API_KEY=sk-여기에_API_키
```

3. Python에서 불러오기

```python
from dotenv import load_dotenv
from openai import OpenAI

load_dotenv()
```

`.env.txt` 사용 시 자동 인식되지 않으므로 다음처럼 파일명을 직접 지정해야 함.

```python
load_dotenv(".env.txt")
```

## 7. LangChain이란?

LangChain은 대규모 언어 모델(LLM)을 애플리케이션에서 쉽게 연결하고 활용하도록 도와주는 Python 프레임워크임.

OpenAI API를 직접 호출하는 것뿐만 아니라 프롬프트 관리, 대화 기록, 문서 검색, 여러 단계의 작업 연결, 외부 도구 호출 등에 활용 가능함.

주요 구성 요소는 다음과 같음.

- `ChatOpenAI`: OpenAI의 대화형 모델 연결함.
- Prompt: 모델에 전달할 질문이나 지시사항 관리함.
- Chain: 여러 작업을 순서대로 연결함.
- Memory: 이전 대화나 실행 결과를 저장함.
- Retriever: 문서나 데이터에서 관련 내용을 검색함.
- Agent: 상황에 따라 적절한 도구와 작업을 선택함.

LangChain을 사용하면 모델 호출 코드를 일정한 방식으로 구성하고, 모델·프롬프트·도구를 교체하거나 확장하기 쉬워짐. 단순한 한 번의 API 호출만 필요하다면 OpenAI SDK를 직접 사용하는 편이 더 간단할 수 있음.

## 8. LangChain `ChatOpenAI`와 `invoke()`

`ChatOpenAI` 객체 생성 시 주요 매개변수 지정 가능함.

```python
from langchain_openai import ChatOpenAI

llm = ChatOpenAI(
    temperature=0.1,          # 응답의 무작위성·창의성 정도
    model_name="gpt-5.6-luna", # 사용할 모델명
)

question = "대한민국의 수도는?"
response = llm.invoke(question)

print(response.content)                  # 답변 내용
print(response.response_metadata)         # 전체 메타데이터
print(response.response_metadata["token_usage"]) # 토큰 사용량
```

### 주요 매개변수

- `model_name`: 호출할 OpenAI 모델 지정함.
- `temperature`: 응답의 무작위성 또는 창의성 정도 조절함. 일반적으로 낮을수록 일관되고 사실 중심의 응답이 나옴.
- `temperature`의 지원 범위와 기본값은 모델마다 다를 수 있으므로 사용할 모델의 공식 문서 확인해야 함.

`invoke()`의 반환값은 단순 문자열이 아니라 LangChain 메시지 객체임. 답변만 확인하려면 `response.content` 사용하고, 토큰·모델명·종료 사유 등은 `response.response_metadata`에서 확인함.

### `logprobs` 오류와 지원 모델

`logprobs`는 출력 토큰별 로그 확률을 확인하는 기능임. 다음과 같이 설정함.

```python
llm_with_logprob = ChatOpenAI(
    model_name="gpt-4o-mini",
    temperature=0.1,
).bind(
    logprobs=True,
    top_logprobs=3,
)
```

주의할 오류가 두 가지 있음.

- `Unsupported parameter: 'logprobs' is not supported with this model.`: 해당 모델이 `logprobs`를 지원하지 않는다는 의미임.

`gpt-5.6-luna`는 현재 `ChatOpenAI`가 사용하는 Chat Completions 방식에서 `logprobs`를 지원하지 않음. 기능 확인 목적이라면 `gpt-4o`, `gpt-4o-mini`, `gpt-4.1`, `gpt-4.1-mini` 등 지원 모델로 테스트하는 것이 적절함.

최신 GPT-5.6 계열은 Responses API에서 별도의 `message.output_text.logprobs` 방식으로 사용할 수 있지만, `ChatOpenAI(...).bind(logprobs=True)`와는 호출 방식이 다름. 단순 토큰 사용량 확인에는 `logprobs` 설정이 필요하지 않으며 `response.response_metadata["token_usage"]`만 확인하면 됨.

## 9. Jupyter Notebook으로 테스트한 이유

실제 테스트는 `page90.ipynb`에서 진행함. Jupyter Notebook은 셀 단위로 필요한 부분만 실행 가능함. 이미 생성한 객체나 실행 결과를 유지하면서 질의 셀만 선택적으로 테스트 가능함.

따라서 초기화 코드와 API 호출을 매번 전체 실행하는 것보다 불필요한 API 재호출 줄일 수 있음. 테스트 과정에서 발생하는 토큰 사용량 관리도 쉬움.

단, Jupyter 사용 자체로 API 호출 1회당 토큰이 자동으로 줄어드는 것은 아님. 토큰 사용량은 실제 입력·출력 내용과 호출 횟수에 따라 결정됨. 테스트 시 `invoke()`는 필요한 경우에만 실행하고, 반복 실행으로 불필요한 호출이 발생하지 않도록 주의해야 함.
