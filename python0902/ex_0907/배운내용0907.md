# Pydantic

Pydantic은 타입 힌트를 이용해 입력 데이터를 검증하고, 가능한 값은 선언한 타입으로 자동 변환해 주는 라이브러리임.

Pydantic의 핵심 역할은 외부에서 받은 데이터가 비즈니스 로직으로 들어가기 전에 올바른 형태인지 검사하고, 사용하기 편한 Python 객체로 변환하는 것임.

| 단계 | 학습 내용 | 핵심 |
| --- | --- | --- |
| 1 | `BaseModel` | 기본 타입 검증과 자동 타입 변환 |
| 2 | `Field`, Optional, Nested Model | 제약 조건과 복잡한 데이터 검증 |
| 3 | API 데이터 모델링 | 요청 데이터 검증 후 비즈니스 로직으로 전달 |

```python
from datetime import datetime
from pydantic import BaseModel, Field, PositiveInt, ValidationError
from typing import Annotated, Literal
from annotated_types import Gt
```

## 1. 기본: 데이터 검증과 타입 변환

### 핵심 개념

- `BaseModel`: Pydantic 모델을 만들 때 상속하는 기본 클래스
- 타입 힌트: 필드에 들어올 데이터의 형태를 정의
- 자동 타입 변환: 변환할 수 있는 입력값은 선언된 타입으로 변환
- `ValidationError`: 데이터가 규칙에 맞지 않을 때 발생하는 예외

`BaseModel`을 상속한 클래스에 필드명과 타입을 선언하면 데이터 모델을 만들 수 있음.

```python
from pydantic import BaseModel

class User(BaseModel):
    # 타입 힌트
    name: str
    age: int
    email: str

user = User(
    name='Hyerim',
    age='28',   # 자동 타입 변환
    email='eeee@gmail.com',
)

print(user)
# name='Hyerim' age=28 email='eeee@gmail.com'

print(user.age)
# 28

print(type(user.age))
# <class 'int'>
```

단, 변환할 수 없는 문자열을 전달하면 `ValidationError`가 발생함.

> `email: str`은 문자열인지만 검사함. 이메일 형식까지 검사하려면 Pydantic의 `EmailStr` 같은 별도의 타입을 사용해야 함.

### 추가 예제: 다양한 타입 자동 변환

```python
class User(BaseModel):
    id: int
    name: str = 'Hyerim Nam'
    signup_ts: datetime | None
    tastes: dict[str, PositiveInt]
```

- `name`을 입력하지 않으면 기본값인 `'Hyerim Nam'`을 사용함.
- `signup_ts`는 `datetime` 또는 `None`을 허용함. 단, 기본값이 없으므로 필드 자체는 반드시 입력해야 함.
- `tastes`는 문자열 키와 0보다 큰 정수 값으로 구성된 딕셔너리임.

딕셔너리 앞의 `**`는 딕셔너리의 키와 값을 키워드 인자로 풀어서 전달함.

```python
external_data = {
    'id': 123,
    'signup_ts': '2026-09-07 10:00',
    'tastes': {
        'wine': 9,
        b'cheese': 7,
        'cabbage': '1',
    },
}

user = User(**external_data)
```

이 과정에서 Pydantic이 입력값을 선언된 타입에 맞게 변환함.

- 날짜 문자열 `'2026-09-07 10:00'` → `datetime` 객체
- 바이트 키 `b'cheese'` → 문자열 키 `'cheese'`
- 숫자 문자열 `'1'` → 정수 `1`
- 생략한 `name` → 기본값 `'Hyerim Nam'`

```python
print(user.model_dump())
# {
#     'id': 123,
#     'name': 'Hyerim Nam',
#     'signup_ts': datetime.datetime(2026, 9, 7, 10, 0),
#     'tastes': {'wine': 9, 'cheese': 7, 'cabbage': 1}
# }
```

### ValidationError

자동 변환할 수 없거나 필수 필드가 빠지면 `ValidationError`가 발생함.

```python
external_data2 = {'id': 'not an int', 'tastes': {}}

try:
    User(**external_data2)
except ValidationError as e:
    print(e.errors())
```

위 예제에서는 다음 두 가지 오류를 확인할 수 있음.

- `id`: `'not an int'`를 정수로 변환할 수 없음
- `signup_ts`: 필수 필드가 누락됨

`e.errors()`는 오류 종류(`type`), 위치(`loc`), 메시지(`msg`), 입력값(`input`) 등을 딕셔너리 목록으로 반환함. 오류를 항목별로 처리하기 좋음.

### 세부적인 타입 제약 조건

```python
class Fruit(BaseModel):
    name: str
    color: Literal['red', 'green']
    weight: Annotated[float, Gt(0)]
    bazam: dict[str, list[tuple[int, bool, float]]]
```

- `Literal['red', 'green']`: `color`에는 `'red'` 또는 `'green'`만 입력할 수 있음.
- `Annotated[float, Gt(0)]`: `weight`는 0보다 큰 실수여야 함.
- `dict[str, list[tuple[int, bool, float]]]`: 문자열 키를 사용하고, 값은 `(정수, 불리언, 실수)` 형태의 튜플을 담은 리스트여야 함.

```python
fruit = Fruit(
    name='Apple',
    color='red',
    weight=4.2,
    bazam={'foobar': [(1, True, 0.1)]},
)
```

## 2. 실전: 기본값, Optional, 중첩 모델

### 핵심 개념

- `Field()`: 값의 범위나 문자열 길이 같은 세부 조건 설정
- `| None`: 값으로 `None`을 허용
- 기본값: 입력을 생략했을 때 사용할 값
- Nested Model: 다른 Pydantic 모델을 필드 타입으로 사용
- 복잡한 JSON 데이터의 구조와 내부 값까지 검증

```python
from pydantic import BaseModel, Field

class Address(BaseModel):
    city: str
    zip_code: str

class User(BaseModel):
    name: str
    age: int = Field(ge=0, le=150)
    email: str
    address: Address
    nickname: str | None = None
```

`Field()`를 사용하면 타입뿐 아니라 값의 범위도 제한할 수 있음.

```python
age: int = Field(ge=0, le=150)
```

- `ge=0`: 0 이상(`age >= 0`)
- `le=150`: 150 이하(`age <= 150`)

`nickname: str | None = None`은 문자열 또는 `None`을 허용하고, 값을 생략하면 기본값으로 `None`을 사용함. `str | None`만 쓰고 기본값을 지정하지 않으면 `None`은 허용하지만 필드 입력 자체는 필수임.

### Nested Model 중첩 모델

```python
user = User(
    name='Hyerim',
    age='28',
    email='email@gmail.com',
    address={
        'city': 'Incheon',
        'zip_code': '00000',
    },
)

print(user.address.city)
# Incheon

print(user.nickname)
# None
```

`address`에 딕셔너리를 전달해도 Pydantic이 내부 데이터를 검증한 뒤 `Address` 객체로 변환함. 따라서 중첩된 JSON 형태의 요청도 모델을 계층적으로 구성해 검증할 수 있음.

## 3. API 요청 → 검증 → 데이터 변환

API에서 받은 값을 바로 비즈니스 로직에 사용하면 필수값 누락, 잘못된 타입, 허용 범위를 벗어난 값 때문에 오류가 발생할 수 있음. 
Pydantic 모델을 요청 데이터와 비즈니스 로직 사이에 두면 먼저 검증된 데이터만 함수에 전달할 수 있음.

```text
API 요청 데이터 → Pydantic 모델 검증·변환 → 비즈니스 로직
```

```python
from pydantic import BaseModel, Field

class SignupRequest(BaseModel):
    username: str = Field(min_length=3, max_length=20)
    password: str = Field(min_length=8)
    age: int = Field(ge=14)

def signup(data: SignupRequest):
    print('회원가입 처리')
    print(f'username: {data.username}')
    print(f'age: {data.age}')

request = SignupRequest(
    username='Hyerim',
    password='12345678',
    age=28,
)

signup(request)
```

각 필드의 검증 조건은 다음과 같음.

- `username`: 3자 이상 20자 이하
- `password`: 8자 이상
- `age`: 14 이상

`SignupRequest` 객체가 정상적으로 생성되었다는 것은 요청 데이터가 선언된 조건을 통과했다는 의미임. `signup()` 함수는 검증 방법을 다시 구현하지 않고, 타입이 보장된 `data.username`, `data.age` 등을 비즈니스 로직에서 사용할 수 있음.

실제 API에서는 일반적으로 다음 순서로 처리함.

1. 클라이언트가 JSON 요청을 보냄.
2. JSON 데이터를 Pydantic 모델로 검증하고 필요한 타입으로 변환함.
3. 검증에 실패하면 오류 응답을 반환함.
4. 검증에 성공하면 모델 객체를 비즈니스 로직에 전달함.
5. 필요한 경우 처리 결과를 딕셔너리나 JSON 문자열로 직렬화함.

### Serialization 직렬화

직렬화는 Pydantic 객체를 딕셔너리나 JSON 문자열과 같은 다른 형식으로 변환하는 것임. 주로 API 응답을 만들거나 JSON 파일에 저장할 때 사용함.

```python
class Meeting(BaseModel):
    when: datetime
    where: bytes
    why: str = 'No idea'

m = Meeting(when='2026-09-07T10:00', where='campus')
```

#### `model_dump()`

Pydantic 객체를 Python 딕셔너리로 변환함.

```python
m.model_dump(exclude_unset=True)
# {'when': datetime.datetime(2026, 9, 7, 10, 0), 'where': b'campus'}
```

`exclude_unset=True`는 객체를 만들 때 직접 입력하지 않은 필드를 제외함. 따라서 기본값을 사용한 `why`가 결과에서 빠짐.

```python
m.model_dump(exclude={'where'}, mode='json')
# {'when': '2026-09-07T10:00:00', 'why': 'No idea'}
```

- `exclude={'where'}`: `where` 필드를 결과에서 제외함.
- `mode='json'`: `datetime`처럼 JSON이 직접 표현할 수 없는 값을 JSON에 맞는 형태로 변환함.

#### `model_dump_json()`

Pydantic 객체를 바로 JSON 문자열로 변환함.

```python
m.model_dump_json(exclude_defaults=True)
# {"when":"2026-09-07T10:00:00","where":"campus"}
```

`exclude_defaults=True`는 현재 값이 기본값과 같은 필드를 제외함. 따라서 기본값인 `why='No idea'`가 빠짐. `model_dump_json()`의 결과는 Python 딕셔너리가 아니라 JSON 문자열이므로 API 전송이나 JSON 파일 저장에 적합함.

#### `model_dump()`와 `model_dump_json()` 비교

| 메서드 | 반환 타입 | 주된 용도 |
| --- | --- | --- |
| `model_dump()` | Python `dict` | Python 코드 내부 처리, 데이터 수정 |
| `model_dump_json()` | JSON 문자열(`str`) | API 전송, JSON 파일 저장 |

# tuple

하나의 변수에 여러 항목을 저장함.
순서가 정해져 있음. 변경 불가능함. 중복 값 허용함.

# 파이썬 컬렉션 비교
* list: 순서O, 변경O, 중복O
* tuple: 순서O, 변경X, 중복O
* set: 순서X, 변경O, 중복X -> 아이템 추가/삭제 가능
* dictionary: 순서O, 변경O, 키 중복X
